# McpGo → ИИ-агент: практическое руководство

> Зачем нужен этот проект: **McpGo превращает вашу Windows-машину в
> инструментальную площадку для ИИ-агента**. Ассистент в чате (в браузере
> или в IDE) по протоколу MCP получает доступ к инструментам — командной
> строке, файловой системе, браузеру, вашим MCP-серверам, — а McpGo
> управляет всей этой инфраструктурой: запускает, наблюдает, переживает
> перезагрузки и публикует наружу через защищённые туннели.

## 1. Как устроен контур агента

```text
┌──────────────┐   MCP (JSON-RPC)   ┌───────────────────────┐
│  ИИ-клиент   │◄──────────────────►│  MCP-сервер(ы)        │
│  (чат/IDE)   │                    │  на вашей машине      │
└──────────────┘                    └──────────┬────────────┘
                                               │ supervise
                                    ┌──────────▼────────────┐
                                    │  McpGo for Windows    │
                                    │  терминал · браузер · │
                                    │  туннели · службы     │
                                    └───────────────────────┘
```

Агентность = у модели появляются **инструменты** (tools): «выполни
команду», «прочитай файл», «открой страницу», «найди в коде». Протокол
MCP (Model Context Protocol) — стандарт, по которому клиент объявляет
серверы и вызывает их инструменты. McpGo закрывает операционную часть:
где эти серверы живут, кто их держит запущенными, как до них достучаться
извне и что делать, когда что-то падает.

## 2. Четыре шага до агента

### Шаг 1. Соберите и поставьте McpGo

```powershell
git clone https://github.com/AligmentInsight/mcpgo-windows.git
cd mcpgo-windows
npm install
npm run tauri build      # MSI + NSIS-инсталлятор
```

После установки откройте раздел **Environment** — он покажет, что нашлось
на машине: PowerShell 7/5.1, Node.js, Chrome, Python. Это runtime-базы,
на которых будут работать инструменты агента.

### Шаг 2. Поднимите MCP-серверы (Terminal + Services)

- **Быстро проверить** — раздел **Terminal**: запустите любой node-процесс
  как задачу, следите за `job_status` / `job_logs`, при необходимости
  отменяйте. Это ваш «ручной режим» управления инструментами.
- **Надолго** — раздел **Services**: оформите MCP-сервер как Windows-службу.
  Определение хранит команду runtime (node / python / powershell) и
  аргументы; McpGo ставит службу `McpGo-<id>` через SCM (UAC-запрос при
  установке — это нормально), а его сервис-воркер сопровождает runtime:
  автозапуск при загрузке системы, перезапуск при падении, журнал.

В качестве первых серверов подходят эталонные MCP-серверы из экосистемы
Model Context Protocol (файловая система, git, fetch и т.п.) и любые
ваши: стандартный сервер — это процесс, который говорит по MCP, а
запустить и сопровождать процесс — как раз работа McpGo.

### Шаг 3. Опубликуйте доступ (Tunnels)

Чтобы клиент мог достучаться до сервера из интернета (например, чат в
браузере, работающий не на вашей машине), используйте раздел **Tunnels**:

1. Создайте туннель на платформе OpenAI (кнопка-ссылка на страницу
   управления туннелями есть в заголовке раздела) и получите его `id`.
2. Добавьте определение в McpGo: цель (`stdio`-команда или `http`
   endpoint локального сервера), регион residency (11 вариантов — от
   `global` до `jp`/`kr`/`sg`/`ae`), при желании `autostart`.
3. Впишите API-ключ один раз — значение сохранится в
   `tunnels\secrets\<id>.key`, наружу отдаётся только ссылка
   `file:<путь>`; повторно ключ не отображается.
4. Нажмите **Start**: McpGo сгенерирует YAML-профиль, запустит
   `mcp-tunnel run --profile-file …`, дождётся ответа health-пробы
   `/healthz` и переведёт туннель в `Running`. Бинарь ищется в порядке:
   путь из определения → PATH → `tunnels\bin` (положите `mcp-tunnel.exe`
   туда, если он не установлен глобально).

`keep_alive` сам перезапустит упавший рантайм в пределах бюджета
перезапусков; лог туннеля читается прямо из карточки.

### Шаг 4. Подключите ИИ-клиента

- **Локальный клиент** (агент в IDE/терминале на той же машине): MCP-сервер
  запускается самим клиентом как stdio-процесс или указывается как
  `http://127.0.0.1:<порт>` — сервер держится службой из шага 2.
- **Удалённый клиент** (чат в браузере, облачный ассистент): добавьте в
  его настройках MCP-подключение по URL туннеля из шага 3 — трафик идёт
  через Secure MCP Tunnel, ключ аутентификации известен платформе.

После подключения у ассистента появляются инструменты этих серверов —
с этого момента «чат» отвечает не только текстом, но и действиями.

## 3. Браузер агента (Browser)

Раздел **Browser** — это CDP-инфраструктура для браузерных инструментов:

- сессия Chrome с собственным профилем и debug-портом из пула
  9222..=9321 (браузерные MCP-серверы подключаются к CDP-эндпоинту
  `127.0.0.1:<порт>`);
- подключение к уже запущенному debug-Chrome (вкладка «attach») — можно
  отдать агенту именно тот браузер, в котором работаете вы;
- список целей `/json/list` — контроль, что страница действительно
  открылась и готова к автоматизации.

Запускайте браузерную сессию прямо перед сессией агента и гасите её
после — карточка сессии показывает состояние и цель CDP.

## 4. Эксплуатация

| Ситуация | Что делает McpGo |
|---|---|
| Перезагрузка Windows | Службы (`McpGo-<id>`) стартуют автоматически; туннели с `autostart` поднимаются при запуске приложения |
| Упал runtime сервера | Сервис-воркер перезапускает процесс; упавший туннель — `keep_alive` в пределах бюджета |
| Нужно понять, что происходило | Журналы задач (`job_logs`), служб и туннелов читаются в соответствующих разделах |
| Ключ скомпрометирован | Перевыпустите на платформе и впишите заново (старое значение нигде не хранится в открытом виде) |

## 5. Безопасность

- Команды терминала выполняются с правами локального пользователя —
  это осознанная модель оригинала: **вы** доверяете **своему** агенту.
- Тяжёлые операции (PowerShell, SCM, ключи) живут в Rust-ядре; webview
  получает только результаты. Значения API-ключей не пересекают IPC и не
  журналируются.
- Публичный доступ открывают только туннели — с аутентификацией
  платформы и в выбранном регионе residency.

## 6. Что дальше

- Обернуть домены McpGo (jobs, browser, tunnels) в собственный MCP-сервер
  «швейцарский нож» — тогда агент сможет управлять инфраструктурой сам
  (запускать задачи, поднимать сессии браузера, рестартовать туннели).
- Добавить в определения служб health-пробы runtime-процессов и метрики
  в Environment.
- CI: GitHub Actions для `cargo check` + `tsc` + статических
  wire-контрактов (те же проверки, что локально — без Rust-тулчейна).
